## 실험 결과: ALS + LLM 앙상블

### 리더보드 결과
- **점수: 0.0338** (-60.8%)
- **대실패**: 기준 ALS(0.0863) 대비 크게 하락

### 원인 분석

#### 1. LLM 임베딩 커버리지 부족 (핵심 원인)
```
전체 아이템: 29,502개
임베딩 보유: 100개 (0.34%)
```
- 대부분의 후보 아이템에서 LLM 유사도가 0으로 계산됨
- 유효한 리랭킹이 거의 불가능

#### 2. 점수 정규화 문제
```python
# 현재 구현
als_norm = (als_score - min) / (max - min)  # 0~1 정규화
llm_sim = cosine_similarity  # -1~1 범위

# 문제점
final = 0.8 * als_norm + 0.2 * llm_sim  # 스케일 불일치
```
- ALS 점수와 LLM 유사도의 스케일이 다름
- LLM 유사도가 0인 경우 ALS 점수만 0.8배 감소 효과

#### 3. 카테고리 부스트 노이즈
- 24개 카테고리 연관지식만으로는 효과 제한적
- 잘못된 보완재 관계가 노이즈로 작용 가능

#### 4. 후보 풀 제한
```python
als_candidates = 100  # 상위 100개만 후보로 사용
```
- ALS Top 100 내에서만 리랭킹
- 원래 ALS가 추천하던 아이템 순서만 변경 (개선 여지 없음)

## 교훈

### 1. LLM 활용의 한계
> "LLM은 은탄환이 아니다"

- **커버리지가 핵심**: 100개 임베딩으로 29,502개 아이템 커버 불가
- **비용 대비 효과**: LLM API 비용 vs 성능 향상 불확실
- **단순한 모델이 강력**: ALS만으로 0.0863 달성

### 2. 앙상블 실패 패턴
```
문제: 보조 모델(LLM)이 주 모델(ALS)을 방해
원인: 커버리지 부족, 스케일 불일치, 노이즈 유입
결과: 앙상블 < 단일 모델
```

### 3. 검증 없는 배포 위험
- 오프라인 검증 없이 제출
- Validation 점수와 리더보드 점수 괴리
